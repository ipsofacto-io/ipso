# ipso

[![OpenSSF Scorecard](https://api.scorecard.dev/projects/github.com/ipsofacto-io/ipso/badge)](https://scorecard.dev/viewer/?uri=github.com/ipsofacto-io/ipso)
[![OpenSSF Best Practices](https://www.bestpractices.dev/projects/15758/badge)](https://www.bestpractices.dev/en/projects/15758)

CLI, check compilers, agent hooks and local MCP server that turn engineering decisions into enforced checks.

> Status: the CLI can initialize a repository, validate EDR files, explain one decision, import MADR or Nygard ADRs, compile in-force checks, and evaluate a Terraform or OpenTofu plan. `ipso premise check` re-checks premises on in-force decisions with a public HTTPS GET. The OPA compiler is registered. A check with `ref: ipso:<provider>/<name>` and `target: terraform-plan` compiles a built-in template. Repository Rego is one `.rego` file. The template list is [docs/templates.md](docs/templates.md). The dependency-cruiser compiler is registered. A check with `engine: depcruise` reads one JSON rule file and writes `depcruise.json`. `ipso check depcruise <path>...` runs `depcruise` from `PATH` on that file. The Semgrep compiler is registered. A check with `engine: semgrep` reads one YAML rule file, or `ref: ipso:<language>/<name>` for a built-in template, and writes `semgrep.yaml`. `ipso check semgrep <path>...` runs the pinned `semgrep` from `PATH` on that file. The template list is [docs/semgrep-templates.md](docs/semgrep-templates.md). The ArchUnit compiler is registered. A check with `engine: archunit` reads one JSON rule file and writes `ArchitectureTest.java`. `ipso check archunit <classes-dir>... --jars <dir>` runs the pinned ArchUnit jars on that file. The rule file is [docs/archunit-rules.md](docs/archunit-rules.md). The import-linter compiler is registered. A check with `engine: importlinter` reads one `.importlinter` file and writes `importlinter.ini`. `ipso check importlinter <source-dir>...` runs the pinned import-linter and grimp from `python` on that file. The Kyverno compiler is registered. A check with `engine: kyverno` reads one ValidatingPolicy YAML file and writes `kyverno.yaml`. `ipso check kyverno <path>...` runs the pinned `kyverno` from `PATH` on that file. A check with `engine: opa` and `target: gatekeeper` reads one YAML file with a ConstraintTemplate and a Constraint and writes `constraint-template.yaml` and `constraint.yaml`. `ipso check gatekeeper <path>...` runs the pinned `gator` from `PATH` on those files. The ESLint compiler is registered. A check with `engine: eslint` reads one JSON rule file and writes `eslint.config.mjs`. `ipso compile` does not run ESLint. `ipso check eslint <path>...` runs the pinned `eslint` from `PATH` on that file. The rule file is [docs/eslint-rules.md](docs/eslint-rules.md). `ipso check plan` evaluates the compiled checks against `terraform show -json` or `tofu show -json` output. The CI-binding compiler is registered. A check with `engine: ci-binding` writes `binding.json` from `job`. `ipso check ci` reads an evidence file for one commit and fails when that job is missing or did not succeed. The Checkov compiler is registered. A check with `engine: checkov` writes `binding.json` from a check id in `ref`. `ipso check checkov` reads a Checkov JSON report and fails when that id failed, was skipped, or was not reported. Neither command calls a network service. The conformance suite compiles the OPA, Semgrep, dependency-cruiser, ArchUnit, import-linter, Kyverno, Gatekeeper, and ESLint fixtures and fails when a pinned engine disagrees with the expected verdict. `ci / conformance` runs it on every pull request and on every push to `main`. `release / conformance` runs it before a tag publishes. Every engine check takes `--sarif <file>` and writes a SARIF 2.1.0 run for GitHub code scanning, as described in [docs/sarif.md](docs/sarif.md). `ipso baseline create|update` records existing violations as fingerprints in `.ipso/baseline.json`, and later checks waive them, as described in [docs/baseline.md](docs/baseline.md). Hooks land in later changes.

This is the Apache-2.0 adoption surface for ipso. One Go workspace will hold the EDR library, the check compilers, the connector SDK, the compiler plugin SDK, policy bundles, the CLI, agent hooks, the local MCP server, rules-file generators and the documentation site.

Module rule: this module does not require `ipso-server`. The EDR JSON Schema is embedded from `edr-spec` so `ipso check` stays offline. `ipso premise check` is the command that fetches a premise URL.

## Install

Pick one:

```bash
brew install ipsofacto-io/tap/ipso
```

```bash
go install github.com/ipsofacto-io/ipso/cmd/ipso@latest
```

Or download a release binary from [GitHub Releases](https://github.com/ipsofacto-io/ipso/releases). Each release publishes `checksums.txt`, keyless cosign signatures, and GitHub artifact attestations. The container image `ghcr.io/ipsofacto-io/ipso` is still private.

## Quick start

From a repository that will hold Engineering Decision Records (EDR files):

```bash
ipso init
ipso check
ipso explain <slug>
```

`ipso init` writes `.ipso/config.yaml` when that file is absent. The default glob is `docs/decisions/**/*.md`. Put EDR Markdown files under that path, then run `ipso check`. Use `ipso explain <slug>` to print the title, status, id, path, sources, and Decision section for one file.

## GitHub Actions

[`ipsofacto-io/ipso-action`](https://github.com/ipsofacto-io/ipso-action) runs one check in a job, uploads its SARIF file to code scanning, and keeps the evidence as an artifact. [docs/github-action.md](docs/github-action.md) has an example workflow.

## Secure use

- `ipso check`, `ipso explain`, `ipso compile`, `ipso check plan`, `ipso check ci`, and `ipso check checkov` run offline. They read local files that match the config globs and do not call a network service. `ipso premise check` performs the public HTTPS GET from ADR-0053. It sends no Authorization header and no cookies, refuses an IP literal, a private address, and a redirect, and it does not edit the EDR.
- The tool validates EDR structure against the embedded draft 0.2 schema. It does not execute decision text as code. `ipso compile` writes artifacts for registered engines. A dependency-cruiser rule file is JSON. Compile validates it and does not execute it. Options that load code, write a cache, or grandfather violations are rejected. An ArchUnit rule file is JSON. Compile validates it and writes a JUnit test that embeds only package patterns. `ipso check archunit` regenerates that test from the verified artifact and refuses anything the generator would not write, so no Java file from the repository is compiled or run. It checks the sha256 of the three pinned jars, copies only `.class` files from the named directories, drops `JAVA_TOOL_OPTIONS`, `JDK_JAVA_OPTIONS`, `_JAVA_OPTIONS`, `JDK_JAVAC_OPTIONS`, and `CLASSPATH`, and runs the JVM in a temporary directory. The JVM inherits the rest of the runner environment, so run that step without secrets. An import-linter file is INI. Compile rejects `contract_types` and a dotted root package, and it does not import repository code. `ipso check importlinter` recovers the contracts from the verified artifact and refuses any config the compiler would not write, so the repository's own `.importlinter` file is never read. It copies only the `*.py` files of each root package and refuses a symlink anywhere below it. It then runs the pinned import-linter and grimp with `python -I` and a finder that answers the root names with that copy and refuses to execute it, so repository Python is parsed and never imported. python inherits the rest of the runner environment, so run that step without secrets. A Kyverno file is one ValidatingPolicy. Compile parses its CEL and rejects context variables that reach the network or the cluster. `ipso check kyverno` compiles the verified `kyverno.yaml` again and requires the same bytes, so the repository's own policy file is never read and an artifact edited together with its manifest is never run. It copies only the `.yaml` and `.yml` files of the named paths, refuses a symlink anywhere below a named directory, drops every `KYVERNO_*` variable, and runs the pinned Kyverno CLI in a temporary directory with no cluster, no registry, and no exception flag. The CLI inherits the rest of the runner environment, so run that step without secrets. A Gatekeeper file is a ConstraintTemplate and a Constraint. Compile type-checks the Rego and rejects `data.inventory` and `http.send`. `ipso check gatekeeper` compiles the verified template and constraint again and requires the same bytes, so the repository's own policy file is never read and an artifact edited together with its manifest is never run. It copies only the `.yaml` and `.yml` files of the named paths, refuses a symlink anywhere below a named directory, refuses a Gatekeeper object, a list that wraps objects, or a document that a YAML parser and gator could read differently, and runs the pinned gator in a temporary directory with no image and no network. gator inherits the runner environment, so run that step without secrets. An ESLint file is JSON. Compile rejects `__proto__` and writes a config that ignores inline disable comments. `ipso check eslint` reads the verified config back into its data, compiles that data again, and refuses any difference, so no JavaScript from the repository or from an edited manifest reaches ESLint. It never loads a repository ESLint config, an `eslint-suppressions.json`, or a directive comment. It needs eslint, typescript-eslint, and TypeScript at the pinned releases in a `node_modules` directory outside the repository, because those packages decide the verdict. It drops every `ESLINT_*` variable and `TIMING`, and ESLint inherits the rest of the runner environment, so run that step without secrets. `ipso check plan` evaluates the compiled Rego against a plan and writes a verdict report. The report carries the plan hash and verdict counts. Resource addresses and messages stay on the terminal. `ipso check ci` and `ipso check checkov` evaluate compiled bindings against a local evidence file. The report carries hashes and verdict counts. Job names, Checkov resource names, and file paths stay on the terminal.
- Prefer release binaries or Homebrew over building unreviewed forks when you need a trusted install. Verify release checksums and signatures when you download from GitHub Releases.
- Report security problems privately through [GitHub private vulnerability reporting](https://github.com/ipsofacto-io/ipso/security/advisories/new). Do not open a public issue for a vulnerability. See the [security policy](https://github.com/ipsofacto-io/.github/blob/main/SECURITY.md).

## Commands

- `ipso init` writes `.ipso/config.yaml` when that file is absent. The default glob is `docs/decisions/**/*.md`.
- `ipso check` validates every matched EDR file against the draft 0.2 schema and the required headings. It does not run check engines.
- `ipso premise check [--report file]` probes premises on decisions that are in force today, the same status and date rule as `ipso compile`. For each premise it performs one public HTTPS GET, compares the JSON pointer with `equals` or `semver`, and prints `<path>: <premise-id>: pass`, `fail`, or `error: <reason>`. It does not read `every`, does not edit the EDR, and does not call the registry. `--report` writes the premise id, the result, the expected and observed values, and the body hash. The report does not contain the response body. Exit 0 when every selected probe passed or failed, including when none were selected. Exit 1 when a probe errored, a record is invalid, or two in-force records share an id. Exit 2 on bad usage.
- `ipso explain <slug>` prints the title, status, id, path, sources, and Decision section of that file.
- `ipso import` rewrites MADR and Nygard ADR files under `docs/adr` and `docs/decisions` into EDR files. Fields the source did not contain are filled in, and `inferred` is set to true. A file that is already a valid EDR file is left unchanged.
- `ipso check plan <plan.json> [--env name] [--input name] [--report file] [--sarif file]` evaluates the compiled checks in `.ipso/build/` against one plan. Run `ipso compile` first, and again after a decision changes: the command trusts the build for status, waivers, and environments, and re-checks only the dates. Without `--env`, checks that name an environment are evaluated too. The plan is the JSON from `terraform show -json` or `tofu show -json`, or `-` to read it from stdin. A check is evaluated when its engine is `opa`, its target is `terraform-plan`, its decision is in force today, and `--env` is absent or the decision applies in that environment. A waiver in force today turns the violations of its decision into a waived result. The report written by `--report` contains the plan hash, the build hash, and one verdict per evaluated check. It does not contain plan values, resource addresses, or messages. With `--bundle <layout> --digest sha256:<hex> --key <public.pem>`, the command verifies that signed OCI layout and does not read `.ipso/build`. An unsigned layout, a bad signature, or a digest that is not the image manifest fails before evaluation. The command does not use the network.
- `ipso bundle pack --layout <dir>` writes an OCI image layout of `.ipso/build` and prints `sha256:<digest>`. `ipso bundle sign --layout <dir> --key <private.pem>` signs that image manifest with an unencrypted PKCS#8 P-256 key and refuses a second signature. `ipso bundle verify --layout <dir> --digest sha256:<hex> --key <public.pem>` checks the pin and the signature. None of these commands use the network. An unsigned layout, a bad signature, or a digest that is not the image manifest fails. The layout directory is mode 0700.
- `ipso compile` compiles checks on records that are in force today. A record is in force when its status is `accepted`, `verified`, or `needs-review` and today falls in `[valid_from, valid_to)`. It replaces `.ipso/build/` with a manifest and the artifact files. The directory contains a `.gitignore` of `*`. A check with no registered compiler is reported and skipped. `llm-advisory` is reported as advisory and is not compiled. An explicit check `mode` is kept. Otherwise `blocking`, `warning`, and `advisory` become `block`, `warn`, and `advise`. For `engine: opa`, `ref: ipso:<provider>/<name>` selects a built-in Terraform plan template and requires `target: terraform-plan`. Any other `ref` is one Rego file in the repository. The compiler writes `policy.rego` after the module parses, and `terraform.rego` for a template. It does not evaluate the plan. For `engine: depcruise`, `ref` is one JSON rule file in the repository. The compiler writes `depcruise.json` and does not run dependency-cruiser. Rule severity follows the check mode (`block` to `error`, `warn` stays `warn`, `advise` to `info`), and a rule set to `ignore` stays `ignore`. `extends` is rejected. So are options that load code, select another compiler, follow symlinks, or write files (`webpackConfig`, `babelConfig`, `cache`, `externalModuleResolutionStrategy`, `parser`, `detectJSDocImports`, `detectImportsInAmbientModules`, `preserveSymlinks`), options that grandfather violations (`knownViolations`, `baseline`, `ignoreKnown`), and options that only shape a report (`focus`, `reaches`, `highlight`, `collapse`, `affected`, `prefix`, `suffix`, `progress`, `reporterOptions`). `baseDir` and `tsConfig.fileName` must stay inside the repository. `doNotFollow`, `exclude`, and `includeOnly` are regular expressions, not paths. Run the result from the repository root with `depcruise --config .ipso/build/<decision-id>/<check-index>/depcruise.json <paths>`, or with `ipso check depcruise <path>...`. That command runs `depcruise` from `PATH` on a temporary copy of the verified config. The binary version must satisfy a caret range of the compiled `compiler_version` (today `^18.7.0`). Each check has 10 minutes. A missing binary, a version outside that range, a cruise that reports an environment issue, or a cruise that finds no modules fails the check. For `engine: semgrep`, `ref` is one `.yaml` or `.yml` rule file, or `ipso:<language>/<name>` for a built-in template ([docs/semgrep-templates.md](docs/semgrep-templates.md)). The compiler writes `semgrep.yaml`. Severity follows the check mode (`block` to `ERROR`, `warn` to `WARNING`, `advise` to `INFO`). Autofix, join mode, extract mode, and version gates are rejected. `options` keeps a closed list of Semgrep 1.182.1 matching options and rejects `interfile`, `taint_match_on`, `commutative_compop`, and any other key. Run the result from the repository root with `ipso check semgrep <path>...`. That command runs the pinned `semgrep` from `PATH` on a temporary copy of the verified config. The binary version must equal the compiled `compiler_version` (today `1.182.1`). Each distinct config has 10 minutes. A missing binary, a version that is not the pin, a scan that reports an error or skips a rule, or a scan that checks no files fails the check. For `engine: archunit`, `ref` is one JSON rule file in the repository. The compiler writes `ArchitectureTest.java` and does not run ArchUnit. The rule file is [docs/archunit-rules.md](docs/archunit-rules.md). Add `.ipso/build` as a test source root, with ArchUnit 1.5.1 and JUnit Jupiter on the test classpath. Or run `ipso check archunit <classes-dir>... --jars <dir>` from the repository root after the build. That command regenerates the test from the verified artifact, compiles it with `javac` from `PATH`, and runs it with the pinned jars and the JUnit console in a separate JVM for each check. `<classes-dir>` is a compiled class directory such as `target/classes`. `--jars` is a directory that holds the three pinned jars ([docs/archunit-rules.md](docs/archunit-rules.md)). Each check has 10 minutes for `javac` and the JVM together. A missing or modified jar, a JDK older than 17, a named directory that is missing or holds a symlink, a rule that checks no classes, or a tree with no class file under the imported packages fails the check. For `engine: importlinter`, `ref` is one `.importlinter` file. The compiler writes `importlinter.ini` and does not run import-linter. It accepts the five built-in contract types in import-linter 2.15 and rejects `contract_types`, report-only keys, and a dotted root package. A layers list and an independence module list need at least two entries. Run the result from the repository root with `lint-imports --config .ipso/build/<decision-id>/<check-index>/importlinter.ini --no-cache`, with the repository's packages importable. Or run `ipso check importlinter <source-dir>...` from the repository root after the build. `<source-dir>` is a directory that holds root packages, such as `.` or `src`. Each root package must have a `__init__.py` in exactly one of the named directories. That command runs `python` from `PATH`, which must carry import-linter 2.15 and grimp 3.18 from the hash-locked requirements, on the canonical config and a copy of the sources, in a separate process for each check with 10 minutes each. A violation is one rendered chain, one illegal import, or one module that is not a layer. A missing python, another import-linter or grimp release, a named directory that is missing or holds a symlink, a root package that is not found, a root named like a module the engine imports, a run that reports an engine error, or output that is not the report ipso reads fails the check. A wildcard module expression, or a layers contract whose layers are all optional, that matches nothing keeps import-linter's own result. For `engine: kyverno`, `ref` is one `.yaml` or `.yml` ValidatingPolicy. The compiler writes `kyverno.yaml` and does not run Kyverno. `validationActions` follows the check mode (`block` to `Deny`, `warn` to `Warn`, `advise` to `Audit`). Context variables `http`, `image`, `resource`, `globalContext`, and `generator` are rejected. Run the result with `kyverno apply .ipso/build/<decision-id>/<check-index>/kyverno.yaml --resource <manifest> --policy-report --output-format json`. Or run `ipso check kyverno <path>...` from the repository root after the build. `<path>` is a manifest file or a directory. That command runs `kyverno` from `PATH`, which must be release 1.19.2 (the pin in `internal/compiler/kyverno/testdata/tool/bin.lock`), on the canonical policy and a copy of the `.yaml` and `.yml` files of the named paths, in a separate process for each check with 10 minutes each. A violation is one resource that fails the policy. A missing binary, another release, a named path that is missing or holds a symlink, a tree with no manifest, a manifest the CLI cannot load, two manifests that name the same resource, a result that is an error, or output that is not the report ipso reads fails the check. A tree with no resource that the policy matches passes. For `engine: opa` and `target: gatekeeper`, `ref` is one YAML file with a ConstraintTemplate and a Constraint. The compiler writes `constraint-template.yaml` and `constraint.yaml` and does not run gator. Rego is v1. `enforcementAction` follows the check mode (`block` to `deny`, `warn` stays `warn`, `advise` to `dryrun`). `data.inventory` and `import rego.v1` are rejected. Run the result with `gator test -f .ipso/build/<decision-id>/<check-index>/constraint-template.yaml -f .ipso/build/<decision-id>/<check-index>/constraint.yaml -f <manifest> -o json`. Or run `ipso check gatekeeper <path>...` from the repository root after the build. `<path>` is a manifest file or a directory. That command runs `gator` from `PATH`, which must be release 3.23.1 with OPA v1.17.1 (the pin in `internal/compiler/opa/testdata/tool/bin.lock`), on the canonical template and constraint and a copy of the `.yaml` and `.yml` files of the named paths, in a separate process for each check with 10 minutes each. A violation is one result for one object. A missing binary, another release, a named path that is missing or holds a symlink, a tree with no manifest or no object, a Gatekeeper object or a list among the manifests, a manifest gator cannot load, or output that is not the result ipso reads fails the check. For `engine: eslint`, `ref` is one JSON rule file and `target` is `javascript` or `typescript`. The compiler writes `eslint.config.mjs` and does not run ESLint. The rule file is [docs/eslint-rules.md](docs/eslint-rules.md). Severity follows the check mode (`block` to `error`, `warn` and `advise` to `warn`). The config sets `noInlineConfig`. Run the result from the repository root with `eslint --config .ipso/build/<decision-id>/<check-index>/eslint.config.mjs --suppressions-location <suppressions.json>`, where that file holds `{}`. `ipso check eslint <path>...` does that for every in-force check: it runs the pinned `eslint` from `PATH` on the verified config, with a suppressions file that holds `{}`, over the named files and directories, and applies the check mode, waivers, and environment. A missing binary, another release, a toolchain inside the repository, a named path that is missing, a file that could not be parsed, a suppression that hid a finding, a run that lints no file, or output that is not the result ipso reads fails the check. For `engine: ci-binding`, `job` is the name of an existing CI job. The compiler writes `binding.json` and does not call the CI provider. `ipso check ci <evidence.json> --sha <sha>` fails when that job is missing from the evidence file or did not conclude `success`. For `engine: checkov`, `ref` is a Checkov id such as `CKV_AWS_24`. The compiler writes `binding.json` and does not run Checkov. `ipso check checkov <results.json>` fails when that id is failed, skipped, or absent. Do not pass `--quiet` to Checkov: that JSON drops passed checks, so a check that passed is reported as not reported.

## CI job evidence

`ipso check ci` does not call GitHub. It trusts the evidence file and `--sha`. The workflow below is what keeps another app from spoofing a job name: it asks only for check runs from the GitHub Actions app, `app_id` 15368. `$SHA` is the pull request head, which is the commit the jobs ran on. The job needs `checks: read`.

```yaml
permissions:
  checks: read
  contents: read
steps:
  - uses: actions/checkout@v4
  - name: Job evidence
    env:
      SHA: ${{ github.event.pull_request.head.sha || github.sha }}
      GH_TOKEN: ${{ github.token }}
    run: |
      gh api --method GET -H "Accept: application/vnd.github+json" \
        "repos/${{ github.repository }}/commits/${SHA}/check-runs?filter=latest&app_id=15368&per_page=100" \
        --jq '{evidence_version:1, sha:env.SHA, jobs:[.check_runs[] | {name:.name, conclusion:.conclusion}]}' \
        > evidence.json
      ipso check ci evidence.json --sha "$SHA"
```

`gh` reads `GH_TOKEN`. `env.SHA` is how `gh --jq` reads the environment. A job that has not finished has `conclusion: null`, and the verdict fails closed. ipso trusts the evidence file and `--sha`. Write the file in this job. The SHA is `github.event.pull_request.head.sha` or `github.sha`. This snippet reads one page of 100 check runs. A repository with more must paginate. A job that is not in the file fails closed.

## CLI reference

Working directory is the repository root. There are no global flags beyond help and version.

| Invocation | Effect |
| --- | --- |
| `ipso init` | Create `.ipso/config.yaml` with `decisions: [docs/decisions/**/*.md]` when missing. Print `wrote .ipso/config.yaml` or `.ipso/config.yaml already exists`. Exit `0`, or `1` on I/O error, or `2` on bad usage. |
| `ipso check` | Load config (or the default globs), match EDR files, validate each. Print `<path>: ok`, `<path>: <problem>`, or `no EDR files found`. Exit `0` when every file is valid or none match, `1` when any file fails, `2` on bad usage. |
| `ipso explain <slug>` | Find the EDR whose front matter `slug` matches. Print `title:`, `status:`, `id:`, `path:`, any `sources:`, then the `## Decision` body. Exit `0` on success, `1` when missing or ambiguous, `2` on bad usage. |
| `ipso baseline create\|update <subcommand> <args>` | Run one engine check with the arguments of `ipso check` and record or trim fingerprints in `.ipso/baseline.json`, one set per `--env` and `--input`. `create` adds entries only for checks with none for that input. `update` only removes fingerprints that no longer occur. Run `ipso compile` afterwards. `ci` is refused. Exit `0` on success even with violations, `1` on errors or `update` with no file, `2` on bad usage. |
| `ipso import [path...]` | Rewrite each MADR or Nygard Markdown file in place as an EDR file. With no path, use `docs/adr` and `docs/decisions`. Print `<path>: imported inferred`, `<path>: skipped` for a file that already validates, `<path>: <problem>`, or `no ADR files found`. Exit `0` when every file is imported, skipped, or none are found, `1` when any file fails, `2` on bad usage. |
| `ipso check plan <plan.json\|-> [--env name] [--input name] [--report file] [--sarif file] [--bundle dir --digest sha256:hex --key public.pem]` | Evaluate compiled `terraform-plan` checks in `.ipso/build/` against one plan. Print `<slug>: checks[N] (mode): pass`, `<slug>: checks[N] (mode): waived`, `<slug>: checks[N] (mode): <address>: <message>`, or `<slug>: checks[N] (mode): error: <reason>`. Exit `0` when no block-mode check has a violation and no check errors, `1` when one does, when the plan is not a plan, or when `.ipso/build` is missing or its artifacts do not match the manifest, `2` on bad usage. With `--bundle`, verify that OCI layout and evaluate it instead of `.ipso/build`. An unsigned layout, a bad signature, or a mismatched digest exits `1` before evaluation. |
| `ipso bundle pack --layout dir` | Write an OCI layout of `.ipso/build` and print `sha256:<digest>`. Exit `0` on success, `1` when the build is missing or the layout cannot be written, `2` on bad usage. |
| `ipso bundle sign --layout dir --key private.pem` | Sign the layout's image manifest with an unencrypted PKCS#8 P-256 key. Print the same digest. Exit `1` when the layout is already signed or the key is not a P-256 PKCS#8 key. |
| `ipso bundle verify --layout dir --digest sha256:hex --key public.pem` | Check the pin and the signature, then the artifact hashes. Print the digest. Exit `1` when the layout is unsigned, the digest does not match, or the signature is not valid. The command does not use the network. |
| `ipso check ci <evidence.json\|-> --sha <sha> [--env name] [--report file] [--sarif file]` | Evaluate compiled `ci-binding` checks against a job evidence file for that commit. ### Config

`.ipso/config.yaml`:

```yaml
decisions:
  - docs/decisions/**/*.md
```

`decisions` must list at least one glob. Paths are relative to the repository root. A missing config file uses the default above.

### Exit codes

| Code | Meaning |
| --- | --- |
| `0` | Success |
| `1` | Runtime failure (I/O, validation failure, missing or ambiguous slug) |
| `2` | Usage error |

## Release

A push to `main` opens a release-please pull request. Merging it tags `vX.Y.Z`. From v0.1.1, that tag is built by the pinned reusable workflow in `ipsofacto-io/.github`. The build publishes binaries, `checksums.txt`, a CycloneDX SBOM, keyless cosign signatures, and GitHub artifact attestations. The image is `ghcr.io/ipsofacto-io/ipso`. v0.1.1 is the first SLSA Build Level 3 release. v0.1.0 keeps its original bytes and has cosign signatures and a CycloneDX SBOM; it is not Level 3. The GHCR package is still private. The Homebrew formula is published to `ipsofacto-io/homebrew-tap` when `HOMEBREW_TAP_TOKEN` is set on this repository.
